# mobile-starter

A React Native starter kit on **Expo SDK 57** (RN 0.86, React 19) with unit tests,
E2E tests, typechecking and linting — verified green on a real iOS simulator and a
real Android emulator, not just in theory.

It exists so that other projects, and the agents working in them, can adopt a
mobile setup that is already debugged.

```bash
npx degit mutaaf/mobile-starter my-app
cd my-app && npm install
npm run verify
npm run ios          # or: npm run android
```

- **Adopting this in an existing project** → [`docs/ADOPTING.md`](docs/ADOPTING.md),
  including what does and doesn't port from a web app.
- **Working in it as an agent** → [`AGENTS.md`](AGENTS.md). Treat its "Invariants"
  section as binding.

After cloning, rename the app in `app.json` (`name`, `slug`, `scheme`,
`ios.bundleIdentifier`, `android.package`) and update `appId` in `.maestro/*.yaml`
to match — otherwise the E2E flows will launch nothing.

## Commands

```bash
npm run verify        # typecheck + lint + unit tests — the gate
npm test              # unit tests
npm run typecheck
npm run lint

npm start             # Metro dev server
npm run ios           # build + install + launch on iOS simulator
npm run android       # build + install + launch on Android emulator

npm run e2e:ios       # Maestro, against a running simulator
npm run e2e:android   # Maestro, against a running emulator
```

The first `npm run ios` / `npm run android` runs `expo prebuild` and compiles a
**development build** — several minutes. After that, JS changes hot-reload and you
only rebuild when native dependencies change.

`ios/` and `android/` are generated by prebuild (Continuous Native Generation) and
are gitignored. Don't hand-edit them; express native config through `app.json`
plugins. `npx expo prebuild --clean` regenerates them.

## Testing

| Layer | Command | Tool |
|---|---|---|
| Types | `npm run typecheck` | TypeScript (strict) |
| Lint | `npm run lint` | ESLint via `expo lint` |
| Unit / component | `npm test` | Jest + `jest-expo` + React Native Testing Library |
| End-to-end | `npm run e2e:ios` / `e2e:android` | Maestro |

CI runs all four on every push: fast checks on Ubuntu, plus real Android emulator
and iOS simulator E2E jobs. See [`.github/workflows/ci.yml`](.github/workflows/ci.yml).

### Unit tests

Live in `__tests__/`, deliberately outside `src/app/` so expo-router never
mistakes them for routes. Import `render` from [`test-utils.tsx`](test-utils.tsx),
not from RNTL directly — it wraps components in `SafeAreaProvider` with fixed
metrics, which screens calling `useSafeAreaInsets()` require.

**`render` is async in React Native Testing Library v14** (React 19 renders
through a concurrent root). Always await it:

```tsx
await render(<HomeScreen />);
expect(screen.getByText('Try editing')).toBeOnTheScreen();
```

Forgetting `await` makes every query throw ``` `render` function has not been
called ```, which looks like a setup problem but isn't. Matchers such as
`toBeOnTheScreen()` are registered automatically in v13+; there is no
`extend-expect` import.

### E2E tests

Maestro flows are in `.maestro/`. They need a **running simulator/emulator with
the app already installed**, so build first:

```bash
npm run ios          # leave the simulator running
npm run e2e:ios
```

The same flow file runs on both platforms.

**Assert on `testID`, not visible text, wherever an element contains an icon.**
iOS folds a child SF Symbol's name into the parent's accessibility label, so the
docs link reads as `"Expo documentation, arrow.up.right.square"` on iOS but plain
`"Expo documentation"` on Android — a text assertion passes on one and fails on
the other. `testID` maps to `accessibilityIdentifier` (iOS) and `resource-id`
(Android), so it matches identically. Inspect what the runner actually sees with:

```bash
maestro hierarchy
```

`__tests__/explore-screen.test.tsx` asserts that testID exists, so removing it
fails in `npm run verify` rather than only in E2E.

## Jest configuration notes

Three things in `package.json`'s `jest` block are load-bearing:

- `preset: "jest-expo"` — transforms Expo/RN modules. Its own
  `transformIgnorePatterns` is inherited deliberately; overriding it locally goes
  stale as expo-router adds untranspiled ESM dependencies (`standard-navigation`
  was one).
- `resolver: "react-native-worklets/jest/resolver.js"` — Reanimated 4 pulls in
  `react-native-worklets`, whose `.native` entry point crashes under Node. This
  resolver steers it to the non-native build.
- `moduleNameMapper` — mirrors the `tsconfig.json` path aliases (Jest does not
  read them), plus a stub for `.css` imports.

Ambient declarations for CSS imports live in `types/css.d.ts`.

## Debugging

**React Native DevTools** is the debugger: press `j` in the Metro terminal, or
`cmd+d` (iOS) / `cmd+m` (Android) → Open Debugger. Flipper is dead — don't install
it. For bundle size, `npx expo-atlas`.

## Scope

What this kit does **not** include, so you can plan around it: no EAS build or
submission pipeline, no auth, no data layer, and an E2E suite that is one smoke
flow proving the harness works rather than real coverage. See the end of
[`docs/ADOPTING.md`](docs/ADOPTING.md).
