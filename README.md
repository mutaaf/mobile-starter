# mobile-starter

A React Native starter kit on **Expo SDK 57** (RN 0.86, React 19) with unit tests,
E2E tests, typechecking and linting — verified green on a real iOS simulator and a
real Android emulator, not just in theory.

It exists so that other projects, and the agents working in them, can adopt a
mobile setup that is already debugged.

## The demo app: Ground Station

The scaffold is a working telemetry console, not a placeholder screen — so the
harness is proven against real network, real sensors and real gesture handling
rather than static text.

| Tab | Live source | Interaction it demonstrates |
|---|---|---|
| **Orbit** | ISS position, `wheretheiss.at` | 4s polling, an animated ground track interpolated between fixes, a hand-authored Lottie pulse |
| **Seismic** | USGS earthquakes, M2.5+/24h | Long list with magnitude-scaled bars and staggered entrance |
| **Aurora** | Planetary Kp, NOAA SWPC | Animated SVG gauge, and a **scrubbable** 6-hour sparkline driven entirely on the UI thread |
| **Launch** | Launch Library 2 manifest | Twenty **live countdowns** ticking from one shared clock, at zero React renders |
| **Motion** | On-device sensors | Accelerometer/gyroscope bubble level, haptics on crossing level, pan+pinch gesture card |
| **Brief** | Your own LLM key | Fuses all four feeds **plus** the handset's sensors into one prompt — Anthropic, OpenAI or Gemini, key held in the device keystore |

### Bring your own key

The Brief tab is the one screen that needs a credential, and it is deliberately
the user's own. Pick Anthropic, OpenAI or Gemini, paste a key, and it is
**verified before it is stored** — a key that never worked is never saved.

Storage is `expo-secure-store` (iOS Keychain / Android EncryptedSharedPreferences),
never the resource cache: that tier persists to AsyncStorage as plain text and
the devtools panel dumps its contents. Keys are masked in the UI, never logged,
never echoed in an error, and never placed in a URL — only in a request header.
`__tests__/llm.test.ts` asserts each of those properties.

What it demonstrates is the actual point: a phone holding four live public feeds
and its own inertial sensors can hand a model a situation no single API knows
about, and get back one synthesised judgement. The briefing reads the caches the
other tabs already filled, so it issues no extra network calls of its own.

The first four APIs are public, keyless and HTTPS — nothing to configure, no secrets in
the repo. Icons and the Lottie asset are generated by scripts in `scripts/`
rather than vendored, so there is no licensing question and the marks are
editable as code.

Everything degrades honestly: the Motion tab detects that simulators expose no
accelerometer and says so instead of showing frozen zeros.

## Architecture

```
screen  →  useResource(key, fetcher)     // subscribes, never fetches
           ↓
       ResourceCache                     // lifecycle, dedup, SWR, events, stats
           ↓
        CacheStore  (interface)
           ↓
     TieredStore → MemoryStore + AsyncStorageStore
```

Screens never fetch. They call `useResource` with a key from `CacheKeys` and
render what comes back, so every request goes through one place that handles
stale-while-revalidate, single-flight dedup, persistence and instrumentation. The
cache is injected through `<CacheProvider>` rather than imported as a singleton,
so tests mount a memory-only instance.

A cold start paints from the previous session's data (memory in front of disk)
while the network catches up. Adding a data source is three steps: a fetcher in
`src/lib/api.ts`, a key in `CacheKeys`, a `useResource` call.

## Devtools overlay

Drag the FPS badge in the bottom-right, or tap it to open the inspector:

| Tab | What it gives you |
|---|---|
| **Cache** | Live entries with age, size, source and fresh/stale/expired/pinned state — plus per-key invalidate, release and evict |
| **Events** | A rolling timeline of every hit, miss, dedup, fetch and error with timings |
| **Perf** | JS-thread FPS, worklet tick rate, cache hit rate and fetch timings |
| **Inject** | Force offline, fail the next request, or add 400ms–3s of latency |

Injection applies to every screen at once because it goes through the cache, so
you can exercise loading, stale and error states without touching a call site or
unplugging anything.

A note on the meters, because it is easy to get wrong: **`useFrameCallback` is not
a vsync frame counter.** Measured here it fired ~8x/sec while Android's own
`dumpsys gfxinfo` reported a 28ms median frame (~35fps). So the badge shows
JS-thread FPS via `requestAnimationFrame`, which is honest and is where RN jank
actually originates; the worklet tick rate is labelled as exactly that. For
authoritative render statistics, use `adb shell dumpsys gfxinfo <package>`.

## Commands

```bash
npm run verify        # typecheck + lint + unit tests — the gate
npm test              # unit tests
npm run typecheck
npm run lint

npm start             # Metro dev server
npm run ios           # build + install + launch on iOS simulator
npm run android       # build + install + launch on Android emulator

npm run e2e:ios       # Maestro, against a running simulator
npm run e2e:android   # Maestro, against a running emulator
```

The first `npm run ios` / `npm run android` runs `expo prebuild` and compiles a
**development build** — several minutes. After that, JS changes hot-reload and you
only rebuild when native dependencies change.

`ios/` and `android/` are generated by prebuild (Continuous Native Generation) and
are gitignored. Don't hand-edit them; express native config through `app.json`
plugins. `npx expo prebuild --clean` regenerates them.

## Testing

| Layer | Command | Tool |
|---|---|---|
| Types | `npm run typecheck` | TypeScript (strict) |
| Lint | `npm run lint` | ESLint via `expo lint` |
| Unit / component | `npm test` | Jest + `jest-expo` + React Native Testing Library |
| End-to-end | `npm run e2e:ios` / `e2e:android` | Maestro |

CI runs all four on every push: fast checks on Ubuntu, plus real Android emulator
and iOS simulator E2E jobs. See [`.github/workflows/ci.yml`](.github/workflows/ci.yml).

### Unit tests

Live in `__tests__/`, deliberately outside `src/app/` so expo-router never
mistakes them for routes. Import `render` from [`test-utils.tsx`](test-utils.tsx),
not from RNTL directly — it wraps components in `SafeAreaProvider` with fixed
metrics, which screens calling `useSafeAreaInsets()` require.

**`render` is async in React Native Testing Library v14** (React 19 renders
through a concurrent root). Always await it:

```tsx
await render(<HomeScreen />);
expect(screen.getByText('Try editing')).toBeOnTheScreen();
```

Forgetting `await` makes every query throw ``` `render` function has not been
called ```, which looks like a setup problem but isn't. Matchers such as
`toBeOnTheScreen()` are registered automatically in v13+; there is no
`extend-expect` import.

### E2E tests

Maestro flows are in `.maestro/`. They need a **running simulator/emulator with
the app already installed**, so build first:

```bash
npm run ios          # leave the simulator running
npm run e2e:ios
```

The same flow file runs on both platforms.

**Assert on `testID`, not visible text, wherever an element contains an icon.**
iOS folds a child SF Symbol's name into the parent's accessibility label, so an
icon-bearing control reads as `"Label, symbol.name"` on iOS but plain `"Label"` on
Android — a text assertion passes on one and fails on the other. `testID` maps to
`accessibilityIdentifier` (iOS) and `resource-id` (Android), so it matches
identically. Inspect what the runner actually sees with:

```bash
maestro hierarchy
```

`__tests__/motion-screen.test.tsx` asserts the testIDs the flows depend on, so
removing one fails in `npm run verify` rather than only in E2E.

## Jest configuration notes

Three things in `package.json`'s `jest` block are load-bearing:

- `preset: "jest-expo"` — transforms Expo/RN modules. Its own
  `transformIgnorePatterns` is inherited deliberately; overriding it locally goes
  stale as expo-router adds untranspiled ESM dependencies (`standard-navigation`
  was one).
- `resolver: "react-native-worklets/jest/resolver.js"` — Reanimated 4 pulls in
  `react-native-worklets`, whose `.native` entry point crashes under Node. This
  resolver steers it to the non-native build.
- `moduleNameMapper` — mirrors the `tsconfig.json` path aliases (Jest does not
  read them), plus a stub for `.css` imports.

Ambient declarations for CSS imports live in `types/css.d.ts`.

## Debugging

**React Native DevTools** is the debugger: press `j` in the Metro terminal, or
`cmd+d` (iOS) / `cmd+m` (Android) → Open Debugger. Flipper is dead — don't install
it. For bundle size, `npx expo-atlas`.

## Shipping it

[`docs/DISTRIBUTION.md`](docs/DISTRIBUTION.md) covers producing installable
artifacts. In short: a sideloadable **APK builds locally with no account**, and
`eas.json` is already configured for both platforms. A device-installable **IPA
requires an Apple Developer account** ($99/yr) — Apple has no unsigned path. An
iOS simulator build is free.

## Scope

What this kit does **not** include, so you can plan around it: no auth, no data
layer beyond the two demo feeds, no store submission, and an E2E suite that is two
short flows proving the harness works rather than real coverage. See the end of
[`docs/ADOPTING.md`](docs/ADOPTING.md).
